# 量化项目架构审阅与优化设计

## 现状结论

项目代码已经形成“热度池 → 历史行情 → 特征 → 逻辑回归 → 时间切分回测 → 信号 → PostgreSQL”的最小闭环。数据库中还存在旧版为分钟行情、资金流、公告、财务、相似度、市场方向和组合管理预留的表，但这些表基本为空，当前有效链路并未使用它们。

主要问题不是缺少表，而是缺少一致的边界和可审计读模型：数据供应商、特征时点、训练运行、样本外净值、信号变化和报表查询此前分散在 CSV、JSON 与多组空表中。

## 已实施优化

1. **配置安全**：数据库连接改由 `QUANT_DB_*` 环境变量覆盖，保留本机默认值。
2. **报表事实表**：新增 `backtest_equity`、`model_feature_weights`、`signal_changes`、`data_quality_snapshots`。
3. **读模型**：新增 `v_latest_model_run` 和 `v_latest_signals`，Web 查询不再复制业务逻辑。
4. **可解释性**：每次运行保存标准化特征系数，可观察模型漂移。
5. **可审计性**：保存每次动作变化、新入榜和移出榜记录。
6. **数据质量**：每次运行记录股票数、行情数、日期覆盖、陈旧股票和下载错误。
7. **Web 报表**：总览、信号筛选、净值曲线、运行历史、特征权重、单股详情与数据质量均从 PostgreSQL 实时读取。

## 仍需优先推进

### P0：从研究回测走向可信纸面交易

- 当前股票池是“今天热榜前 50”，历史回测存在成分回看偏差。必须积累每日/每 10 分钟真实热榜快照，并按当时成分做 walk-forward 回放。
- 当前日线数据不足以验证盘中最佳买卖时机。旧表 `stock_kline_1m` 可以作为分钟数据落点，但必须先确定合规、稳定的数据授权和复权规则。
- 增加涨跌停、停牌、开盘不可成交、成交量容量和真实佣金/印花税模型。
- 纸面交易至少运行 1–3 个月，记录信号时间、可成交价、滑点、撤单和实际收益。

### P1：模型验证

- 把单次 70/15/15 切分升级为 expanding walk-forward，并保留 embargo/gap。
- 对阈值、Top-K 和特征组合进行多重检验修正，报告 Deflated Sharpe 与 bootstrap 置信区间。
- 加入概率校准、Brier score、PR-AUC、分层命中率和行业/市值暴露。
- 使用简单基线（买入持有、均线、横截面动量）做同成本对照，模型不超过基线时自动降级为 HOLD。

### P1：数据与领域模型

- 将旧表分为 `raw_*`、`feature_*`、`model_*`、`signal_*`、`portfolio_*` 五个 schema，避免 `stock_watchlist`/`self_stack`、`bars_daily`/`stock_kline_daily` 等重复概念。
- 引入证券主数据表，统一代码、市场、名称、上市/退市日期和交易状态。
- 行情增加供应商、复权类型、采集时间、校验哈希与修订版本。
- 交易日历接入官方来源；监控不再只按工作日判断。

### P2：服务化与运维

- 将采集、训练、推理、报表拆为独立命令，训练不应每 10 分钟重复执行；盘中仅做增量特征和推理，收盘后再训练。
- 增加 advisory lock，防止定时任务重叠；记录任务耗时、失败步骤和重试次数。
- Web API 后续改用连接池和只读数据库账号；当前 `psql` 适合零依赖本地部署，不适合高并发。
- 增加用户组合、仓位上限、行业集中度、单票风险预算和组合级止损，但保持“建议”和“自动下单”权限隔离。

## 推荐目标架构

`供应商采集 → 原始不可变数据 → 校验/标准化 → Point-in-time 特征 → Walk-forward 训练 → 模型注册 → 实时推理 → 风控门控 → 信号日志 → 纸面交易 → 归因与监控`

Web 报表只读取数据库视图，不直接参与训练或交易，从而保持研究、决策与展示三层解耦。
